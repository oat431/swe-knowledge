# Post-Project Evaluation

> **Core skill:** Evaluating project success against objectives after the project has been closed and the deliverable has been in operation long enough for benefits to materialize — so the organization knows whether the investment paid off and what it should learn for future investments.

## Why This Matters

The project closure report answers "did we deliver what we said we would?" The post-project evaluation answers "did it work?" — the question that can only be answered after the deliverable has been in operation and benefits have had time to materialize. A project that was delivered on time and on budget but whose benefits never materialized is a project whose true evaluation is not "green" but "the business case was wrong, the benefits were overestimated, or the operational environment was not ready."

The post-project evaluation closes the accountability loop that began with the business case. It is the organization's mechanism for learning whether its project investments produce the returns they promised — and the project manager's mechanism for validating (or correcting) the benefits assessment made at closure. A project manager who participates in the post-project evaluation learns what actually happened to the project's outputs and benefits; a project manager who moves on after closure never knows whether the project truly succeeded.

## Timing the Evaluation

| Evaluation Type | Timing | Focus |
|-----------------|--------|-------|
| **Immediate post-project** | 3-6 months after closure | Short-term benefits; operational stability; user adoption |
| **Medium-term** | 6-12 months after closure | Medium-term benefits; sustained adoption; process improvement |
| **Long-term** | 12-24 months after closure | Strategic benefits; organizational impact; ROI |

The timing is determined by the benefits realization timeline in the benefits management plan. An evaluation conducted before benefits have had time to materialize is premature; an evaluation conducted years later has lost the organizational memory to connect outcomes to project decisions.

## The Evaluation Framework

### Dimensions of Post-Project Success

| Dimension | Evaluation Question | Data Sources |
|-----------|---------------------|--------------|
| **Benefits realization** | Did the projected benefits materialize? At what level? | Benefits measurement data; benefit owner reports |
| **Operational performance** | Is the deliverable performing as expected in operations? | Operational metrics; incident data; support tickets |
| **User adoption** | Are users adopting the deliverable at the expected rate? | Adoption metrics; user satisfaction surveys |
| **Business impact** | Did the project produce the intended business outcome? | Business metrics; stakeholder interviews |
| **Schedule and cost accuracy** | How accurate were the project's schedule and cost estimates? | Actual vs. planned comparison; root cause of variance |
| **Risk management effectiveness** | Did the project's risk management successfully mitigate the risks that mattered? | Risk register vs. actual outcomes |
| **Stakeholder satisfaction** | Are stakeholders satisfied with the outcome, now that it is in operation? | Stakeholder survey; sponsor interview |
| **Lessons validation** | Were the lessons identified at closure validated by post-project experience? | Comparison of closure lessons with post-project observations |

### Key Questions

1. Did the project achieve its objectives?
2. Did the benefits materialize as projected?
3. Was the investment justified by the return?
4. What would we do differently if we could do it again?
5. What should the organization learn for future projects?

## Conducting the Evaluation

### Data Collection

| Method | Description | Best For |
|--------|-------------|----------|
| **Benefits measurement** | Actual vs. planned benefit data from benefit owners | Benefits realization |
| **Operational metrics** | System performance, incident rates, support volumes | Operational performance |
| **User survey** | Structured survey of users and stakeholders | Adoption, satisfaction |
| **Sponsor interview** | In-depth interview with the project sponsor | Strategic assessment, lessons |
| **Operations interview** | Interview with the operational owner | Transition quality, sustainment |
| **Document review** | Review of closure report, benefits assessment, lessons learned | Baseline for comparison |

### The Evaluation Report

| Section | Content |
|---------|---------|
| **Executive summary** | Overall assessment: did the project succeed? One-page summary |
| **Project recap** | Brief summary of project objectives, scope, schedule, and cost |
| **Benefits assessment** | Benefits realized vs. planned — with updated measurements |
| **Operational assessment** | Deliverable performance in operations |
| **Adoption assessment** | User adoption vs. targets |
| **Financial assessment** | Actual cost vs. budget; ROI calculation if applicable |
| **Schedule assessment** | Actual timeline vs. baseline |
| **Lessons confirmed** | Which closure lessons were validated; which were revised |
| **New lessons** | Lessons that only became visible post-project |
| **Recommendations** | For the organization: process, estimation, governance improvements |

## The Project Manager's Role

The project manager's role in post-project evaluation:

| Responsibility | Description |
|----------------|-------------|
| **Provide project data** | Closure report, benefits assessment, lessons learned, project metrics |
| **Participate in evaluation** | Interview or contribute to the evaluation process |
| **Learn from the results** | Understand what actually happened to the project's outputs and benefits |
| **Apply to next projects** | Use the evaluation findings to improve estimation, risk management, and benefits planning |

The project manager is not typically the evaluator — the evaluation may be conducted by a PMO, an independent assessor, or the sponsor. But the project manager should seek out the results: the post-project evaluation is the most honest feedback a project manager can receive about their own practice.

## When the Evaluation Is Negative

A negative post-project evaluation is not a project management failure — it is organizational learning:

| Finding | Organizational Response |
|---------|------------------------|
| Benefits not realized | Investigate: was the business case unrealistic? Did assumptions fail? Was adoption insufficient? |
| Operational issues | Improve transition processes; involve operations earlier |
| Adoption shortfall | Improve change management; engage users earlier and more deeply |
| Cost overrun | Improve estimation; calibrate contingency based on project type |
| Schedule slip | Improve dependency management; build buffers for known-risk activities |

The organization that punishes negative evaluations gets no more honest evaluations. The organization that treats negative evaluations as learning opportunities gets better at project investment over time.

## Post-Project Evaluation in Programs

Program post-project evaluation is the capstone:

- **Program evaluation**: assesses the aggregate program benefits, integrated operational performance, and strategic contribution
- **Project evaluations**: feed into the program evaluation; patterns across projects are especially valuable
- **Benefit sustainment**: evaluates whether program benefits are sustained beyond the immediate post-project period — the true test of program success
- **Organizational capability**: evaluates whether the program built lasting organizational capability, not just delivered outputs

## Practical Applications

### Post-Project Evaluation Checklist

- [ ] Evaluation is scheduled at project closure — date and owner for the evaluation
- [ ] Evaluation timing matches the benefits realization timeline
- [ ] Data sources are identified: benefits measurement, operational metrics, surveys, interviews
- [ ] The evaluation report covers benefits, operations, adoption, financials, and lessons
- [ ] Findings are presented to the sponsor and, where appropriate, the steering committee
- [ ] Lessons from the evaluation are integrated into organizational process assets
- [ ] The project manager reviews the evaluation and applies findings to future projects

## Common Pitfalls

| Pitfall | Why It Is a Problem | Better Approach |
|---------|---------------------|-----------------|
| **Never evaluated** | Nobody schedules the evaluation; the project fades from memory | Evaluation scheduled at closure with a named owner |
| **Evaluated too early** | Benefits haven't materialized; evaluation is guesswork | Evaluate at the point where benefits should be measurable |
| **Evaluated too late** | Organizational memory lost; nobody connects outcomes to project decisions | Evaluate within 12 months; earlier for short-term benefits |
| **Benefits-only evaluation** | Evaluation ignores operational and adoption dimensions | Multi-dimensional: benefits, operations, adoption, lessons |
| **Punitive evaluation** | Negative findings are used to blame; honest evaluation stops | Evaluation as learning; findings improve the system, not punish individuals |

## Success Indicators

- Post-project evaluation is scheduled at closure and conducted on time
- Benefits are measured against the benefits management plan — not against memory
- The evaluation is multi-dimensional: benefits, operations, adoption, financials, lessons
- Findings result in organizational process improvements
- The project manager learns from the evaluation and applies findings to the next project

## Summary

Post-project evaluation answers the question that closure cannot: "did it work?" Conducted after the deliverable has been in operation long enough for benefits to materialize, the evaluation assesses benefits realization, operational performance, user adoption, business impact, and the accuracy of the project's estimates and risk management. It closes the accountability loop that began with the business case and provides the organization with its most honest feedback about whether its project investments produce the returns they promise. The project manager who participates in and learns from the post-project evaluation closes their own learning loop; the one who moves on after closure never knows whether the project truly succeeded. The post-project evaluation is the project's final truth — and the organization that seeks it, learns from it, and acts on it gets better at choosing, estimating, and delivering projects with every cycle.
