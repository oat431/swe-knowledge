# Re-prioritization

> Priorities set in January may not be right in June. Re-prioritization is the discipline of adapting priorities as you learn, as markets change, and as execution reveals reality.

## Why Re-prioritization Matters

**Without re-prioritization:**
- Sticking to outdated priorities
- Ignoring new information
- Missing opportunities
- Wasting resources on low-value work

**With re-prioritization:**
- Responsive to learning
- Adaptive to change
- Capturing new opportunities
- Focused on current highest value

## When to Re-prioritize

### 1. Scheduled Reviews

**Regular cadence:**
- Quarterly: Strategic alignment
- Monthly: Roadmap adjustments
- Sprintly: Tactical adjustments

**Benefits:**
- Predictable process
- Prevents drift
- Regular learning integration

### 2. Triggered Reviews

**Re-prioritize when:**
- Strategic direction changes
- Market conditions shift significantly
- Major customer insights emerge
- Competitive landscape changes
- Execution reveals major issues
- Resource constraints emerge

**Example triggers:**
```
Trigger: Competitor launches similar product
Action: Reassess competitive positioning, adjust priorities

Trigger: Customer research reveals different problem
Action: Reframe problem, reprioritize solutions

Trigger: Technical approach not working
Action: Reassess approach, consider alternatives
```

### 3. Continuous Learning

**Learn and adapt:**
- User feedback
- Analytics insights
- Experiment results
- Execution learnings

**Example:**
```
Hypothesis: Users want advanced search
Experiment: Released basic search
Learning: Users don't use search, they use filters
Adaptation: Deprioritize advanced search, prioritize filters
```

## Re-prioritization Process

### 1. Assess Current State

**Review:**
- Current priorities
- Progress made
- What's working
- What's not working

**Questions:**
- Are we making progress on priorities?
- Are priorities still right?
- What have we learned?
- What has changed?

### 2. Gather New Information

**Sources:**
- Customer feedback and research
- Analytics and metrics
- Competitive intelligence
- Market trends
- Execution learnings
- Stakeholder input

### 3. Reassess Opportunities

**Re-evaluate:**
- Value (has it changed?)
- Effort (better estimates?)
- Strategic alignment (still aligned?)
- Risk (new risks?)
- Dependencies (changed?)

### 4. Make Adjustments

**Types of adjustments:**
- **Add:** New high-priority opportunity
- **Remove:** Lower priority than thought
- **Reorder:** Change sequence
- **Rescope:** Adjust scope
- **Defer:** Move to later

### 5. Communicate Changes

**Communicate:**
- What changed
- Why it changed
- What it means for teams
- What stakeholders should do

**Example:**
```
"We're reprioritizing Q3 based on customer research.
Unified customer view remains top priority. We're adding
filter functionality based on user feedback. We're deferring
mobile app to Q4 as research shows web usage is primary.
This means engineering will focus on filters in August
instead of mobile planning."
```

## Re-prioritization Frameworks

### 1. Stop/Start/Continue

**For each initiative:**
- **Stop:** No longer valuable, stop immediately
- **Start:** New high-priority opportunity, start now
- **Continue:** Still valuable, keep going

**Example:**
```
Stop: Advanced reporting (low usage)
Start: Filter functionality (high user demand)
Continue: Unified customer view (strategic priority)
```

### 2. Impact Assessment

**Assess impact of change:**
- What work is affected?
- What resources shift?
- What timelines change?
- What dependencies break?

**Example:**
```
Change: Add filter functionality
Impact:
- Engineering: 2 weeks diverted from mobile
- Design: 1 week for filter design
- Timeline: Mobile delayed by 2 weeks
- Dependencies: None broken
Decision: Worth the trade-off
```

### 3. Scenario Planning

**Consider scenarios:**
- What if we continue current priorities?
- What if we add new priority?
- What if we remove current priority?

**Compare scenarios:**
```
Scenario A: Continue current plan
- Unified view: Q2
- Mobile: Q3
- Expected value: $1.5M

Scenario B: Add filters, defer mobile
- Unified view: Q2
- Filters: Q3
- Mobile: Q4
- Expected value: $1.8M (filters add value)

Decision: Scenario B
```

## Managing Re-prioritization

### 1. Minimize Disruption

**Reduce cost of change:**
- Stable core priorities
- Flexible periphery
- Modular planning
- Buffer capacity

**Example:**
```
Core (stable): Unified customer view (strategic priority)
Flexible: Feature details, sequence within quarter
Buffer: 20% capacity for adjustments
```

### 2. Maintain Alignment

**Keep stakeholders aligned:**
- Regular communication
- Transparent rationale
- Shared understanding
- Collaborative decisions

### 3. Track Changes

**Document:**
- What changed
- Why it changed
- When it changed
- Impact of change

**Benefits:**
- Learn from changes
- Improve prioritization
- Build institutional memory

### 4. Balance Stability and Agility

**Too stable:**
- Ignores learning
- Misses opportunities
- Rigid execution

**Too agile:**
- Constant context switching
- Never finish anything
- Team frustration

**Right balance:**
- Stable strategic direction
- Flexible tactical execution
- Regular but not constant change

## Common Re-prioritization Mistakes

### 1. Reactive Re-prioritization

**Mistake:** Changing priorities with every request
**Fix:** Scheduled reviews, trigger-based changes

### 2. Ignoring Sunk Costs

**Mistake:** Continuing because we've invested
**Fix:** Evaluate based on future value, not past investment

### 3. Poor Communication

**Mistake:** Changing priorities without explanation
**Fix:** Communicate what, why, and impact

### 4. Not Learning

**Mistake:** Same mistakes in reprioritization
**Fix:** Track changes, learn patterns, improve process

### 5. Change for Change's Sake

**Mistake:** Constant changes without good reason
**Fix:** Require evidence and rationale for changes

## Senior-Level Re-prioritization

1. **Strategic adaptation**
   - Not just tactical adjustments
   - Evolve strategy based on learning
   - Maintain strategic coherence

2. **Build adaptive capability**
   - Train teams in adaptation
   - Create re-prioritization processes
   - Build organizational agility

3. **Manage change**
   - Minimize disruption
   - Maintain alignment
   - Build change tolerance

4. **Learn and improve**
   - Track prioritization accuracy
   - Learn from reprioritization
   - Improve over time

## Metrics

- Re-prioritization frequency (changes per quarter)
- Prioritization accuracy (predicted vs. actual value)
- Change impact (disruption caused)
- Adaptation speed (time from learning to change)
- Stakeholder satisfaction with changes
