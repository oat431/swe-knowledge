# Metrics Framework

> You get what you measure, but only if you measure the right things. A metrics framework ensures you're tracking what matters, not just what's easy to measure.

## Why Metrics Frameworks Matter

**Without framework:**
- Measuring everything, learning nothing
- Vanity metrics that look good but don't help
- No connection between metrics and goals
- Conflicting metrics across teams

**With framework:**
- Focused measurement
- Metrics connected to goals
- Clear what success looks like
- Aligned measurement across teams

## Popular Metrics Frameworks

### 1. HEART Framework (Google)

**Five dimensions of user experience:**

**H - Happiness:**
- User satisfaction
- NPS (Net Promoter Score)
- CSAT (Customer Satisfaction)
- Surveys and feedback

**E - Engagement:**
- User interaction depth
- Session frequency
- Feature usage
- Time spent

**A - Adoption:**
- New users starting
- Feature adoption rates
- Onboarding completion
- First key actions

**R - Retention:**
- Users coming back
- Retention rates
- Churn rates
- Cohort retention

**T - Task Success:**
- Task completion rates
- Time to complete
- Error rates
- Efficiency metrics

**When to use:**
- User experience focus
- Balanced measurement
- Multiple stakeholder needs

**Example:**
```
Unified Customer View Metrics (HEART):

Happiness:
- CSAT score target: 4.5/5
- NPS target: 50+

Engagement:
- Daily active users: 80% of target users
- Average sessions per day: 5+

Adoption:
- Week 1 adoption: 60% of eligible users
- Month 1 adoption: 90% of eligible users

Retention:
- Week 4 retention: 85%
- Month 3 retention: 75%

Task Success:
- Customer search time: <30 seconds (from 2 min)
- Task completion rate: 95%
```

### 2. AARRR Framework (Pirate Metrics)

**Five stages of customer lifecycle:**

**A - Acquisition:**
- How do users find you?
- Traffic, sign-ups, downloads
- Source and channel performance
- Cost per acquisition

**A - Activation:**
- Do users have first great experience?
- First key action completed
- Time to value
- Onboarding success

**R - Retention:**
- Do users come back?
- Retention rates by cohort
- Churn rates
- Usage patterns

**R - Referral:**
- Do users tell others?
- Viral coefficient
- Referral rates
- Word of mouth

**R - Revenue:**
- Do you make money?
- Revenue per user
- Customer lifetime value
- Conversion to paid

**When to use:**
- Growth focus
- Funnel optimization
- Business model validation

**Example:**
```
SaaS Product Metrics (AARRR):

Acquisition:
- Monthly sign-ups: 1,000
- Cost per acquisition: $50
- Top channels: Organic (40%), Paid (35%), Referral (25%)

Activation:
- First project created: 70% of sign-ups
- Time to activation: 2 days average
- Onboarding completion: 65%

Retention:
- Month 1 retention: 85%
- Month 6 retention: 70%
- Month 12 retention: 60%

Referral:
- Referral rate: 15% of users refer
- Viral coefficient: 0.3
- NPS: 45

Revenue:
- Trial to paid conversion: 25%
- Monthly revenue per user: $29
- Customer lifetime value: $870
- LTV:CAC ratio: 17:1
```

### 3. North Star Metric

**Single metric that captures core value:**

**Characteristics:**
- Reflects core value delivery
- Actionable and understandable
- Leading indicator of growth
- Measurable frequently

**Examples:**
- Airbnb: Nights booked
- Facebook: Monthly active users
- Spotify: Time spent listening
- Slack: Daily active users sending messages

**When to use:**
- Need single focus metric
- Align organization
- Simplify communication

**Example:**
```
Customer Service Platform:

North Star Metric:
"Calls resolved per hour"

Why:
- Reflects core value (efficiency)
- Actionable (features improve this)
- Leading indicator (efficiency = retention)
- Measurable daily

Supporting metrics:
- Search time per call
- Information completeness
- First-call resolution rate
- Customer satisfaction
```

### 4. OKRs (Objectives and Key Results)

**Goals with measurable outcomes:**

**Structure:**
- Objective: Qualitative goal
- Key Results: Quantitative measures

**Example:**
```
Objective: Improve customer service efficiency

Key Results:
- Reduce average call time from 10 min to 7 min
- Increase first-call resolution from 60% to 80%
- Improve customer satisfaction from 3.2 to 4.0

Measurement:
- Weekly tracking
- Monthly reviews
- Quarterly assessment
```

**When to use:**
- Goal setting
- Alignment
- Progress tracking

## Creating Your Metrics Framework

### 1. Start with Goals

**What are you trying to achieve?**
- Strategic objectives
- Product goals
- User outcomes
- Business outcomes

**Example:**
```
Strategic goal: Improve customer service efficiency
Product goal: Reduce call handling time
User outcome: Reps find information faster
Business outcome: Lower support costs
```

### 2. Identify Success Metrics

**How will you know you succeeded?**
- Outcome metrics (results)
- Process metrics (how you got there)
- Quality metrics (how good)

**Example:**
```
Outcome metrics:
- Average call time: 7 minutes (from 10)
- Customer satisfaction: 4.0 (from 3.2)

Process metrics:
- Search time: 30 seconds (from 2 minutes)
- Information completeness: 95% (from 70%)

Quality metrics:
- First-call resolution: 80% (from 60%)
- Escalation rate: 10% (from 25%)
```

### 3. Define Measurement

**How will you measure?**
- Data sources
- Calculation methods
- Collection frequency
- Reporting format

**Example:**
```
Metric: Average call time
Source: Call system logs
Calculation: Total call time / Number of calls
Frequency: Daily
Report: Weekly dashboard, monthly review
Owner: Product manager
```

### 4. Set Targets

**What does success look like?**
- Baseline (current state)
- Target (desired state)
- Threshold (minimum acceptable)

**Example:**
```
Metric: Customer satisfaction
Baseline: 3.2/5
Target: 4.0/5
Threshold: 3.5/5
Timeframe: 6 months
```

## Metrics Hierarchy

### Strategic Metrics

**Executive level:**
- Business outcomes
- Strategic goal progress
- Market position
- Financial performance

**Example:**
- Revenue growth: 20% YoY
- Customer retention: 90%
- Market share: 15%

### Product Metrics

**Product team level:**
- Product outcomes
- User behavior
- Feature performance
- Quality metrics

**Example:**
- User engagement: 70% DAU/MAU
- Feature adoption: 80%
- Performance: 99.9% uptime

### Feature Metrics

**Feature level:**
- Feature usage
- User satisfaction
- Performance
- Impact

**Example:**
- Search usage: 500 searches/day
- Search satisfaction: 4.2/5
- Search speed: 200ms average

## Common Metrics Framework Mistakes

### 1. Vanity Metrics

**Mistake:** Measuring what looks good, not what matters
**Fix:** Focus on actionable metrics connected to goals

### 2. Too Many Metrics

**Mistake:** Tracking everything, overwhelmed by data
**Fix:** Focus on key metrics that matter

### 3. No Targets

**Mistake:** Measuring without knowing what success looks like
**Fix:** Set clear targets and thresholds

### 4. Inconsistent Definitions

**Mistake:** Different teams calculate metrics differently
**Fix:** Standard definitions and documentation

### 5. Not Acting on Data

**Mistake:** Collecting data but not using it
**Fix:** Connect metrics to decisions and actions

## Senior-Level Metrics Frameworks

1. **Strategic metrics**
   - Not just product metrics

   - Strategic goal tracking

2. **Metrics culture**
   - Build data-driven culture
   - Train teams in metrics
   - Establish standards

3. **Advanced frameworks**
   - Custom frameworks for context
   - Composite metrics
   - Predictive metrics

4. **Metrics governance**
   - Standard definitions
   - Data quality
   - Privacy and ethics
