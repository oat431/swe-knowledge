# Data-Informed Decisions

> Data informs decisions, but doesn't make them. The best product managers combine quantitative data with qualitative insights, intuition, and strategic thinking to make decisions that drive value.

## Why Data-Informed Decisions Matter

**Without data:**
- Decisions based on opinions and politics
- HiPPO (Highest Paid Person's Opinion) dominates
- Can't measure decision quality
- Repeat mistakes

**With data:**
- Evidence-based decisions
- Reduced bias and politics
- Can measure and learn
- Continuous improvement

## Data-Informed vs. Data-Driven

### Data-Informed

**Data is one input:**
- Quantitative data
- Qualitative insights
- Strategic context
- Expert judgment
- Intuition

**Decision process:**
```
1. Gather data (what happened?)
2. Understand context (why?)
3. Consider strategy (what matters?)
4. Apply judgment (what's right?)
5. Make decision (what do we do?)
```

### Data-Driven

**Data is primary input:**
- Heavily weighted toward metrics
- Statistical analysis
- Automated decisions where possible

**Decision process:**
```
1. Define metrics
2. Collect data
3. Analyze statistically
4. Follow data recommendation
```

### When to Use Each

**Data-informed:**
- Strategic decisions
- Complex trade-offs
- Novel situations
- High uncertainty

**Data-driven:**
- Tactical optimizations
- Clear success metrics
- Repeated decisions
- Low risk

## Decision Framework

### 1. Define Decision

**Clarify what you're deciding:**
- Options available
- Decision criteria
- Stakeholders involved
- Timeline for decision

**Example:**
```
Decision: Should we build mobile app in Q2 or Q3?

Options:
A. Build in Q2 (accelerate)
B. Build in Q3 (current plan)
C. Defer to Q4
D. Don't build mobile app

Criteria:
- Strategic alignment
- Customer value
- Technical feasibility
- Resource availability

Stakeholders: Product, Engineering, Design, Executives
Timeline: Decision needed by March 15
```

### 2. Gather Data

**Collect relevant information:**

**Quantitative data:**
- User behavior metrics
- Market data
- Financial projections
- Technical metrics

**Qualitative data:**
- User research
- Customer feedback
- Expert opinions
- Competitive intelligence

**Example:**
```
Quantitative:
- Mobile web usage: 25% of traffic (growing 5%/quarter)
- Competitor mobile apps: 3 of 5 have apps
- Mobile app development cost: $500K
- Expected mobile users: 40% of base within 1 year

Qualitative:
- User interviews: 60% want mobile app
- Sales feedback: Prospects ask about mobile
- Customer support: Mobile issues increasing
- Design team: Excited about mobile challenge
```

### 3. Analyze Data

**Make sense of information:**

**Analysis questions:**
- What does data tell us?
- What patterns emerge?
- What are trade-offs?
- What are risks?

**Example:**
```
Analysis:

User demand: Strong (60% want it, usage growing)
Market pressure: Moderate (3 of 5 competitors have apps)
Financial case: Positive (ROI in 18 months)
Technical feasibility: High (team has experience)
Resource impact: Significant (diverts from other work)

Key trade-off:
Building mobile app means deferring AI features
Mobile app serves existing users better
AI features might attract new users
```

### 4. Consider Context

**Broader factors:**

**Strategic alignment:**
- Does this support our strategy?
- Does it advance our goals?

**Timing:**
- Is now the right time?
- What happens if we wait?

**Opportunity cost:**
- What can't we do if we do this?
- What's the cost of not doing it?

**Example:**
```
Context:

Strategic alignment:
- Strategy focuses on customer efficiency
- Mobile app supports field workers
- Moderate alignment (not core strategic priority)

Timing:
- Mobile usage growing but not urgent
- Could wait 1-2 quarters
- Risk: Competitors might capture mobile market

Opportunity cost:
- Building mobile = deferring AI features
- AI features align better with strategy
- But mobile serves larger current user base
```

### 5. Make Decision

**Synthesize and decide:**

**Decision approaches:**
- Consensus (everyone agrees)
- Consult (gather input, one decides)
- Command (leader decides)

**Example:**
```
Decision process:
- Gathered input from all stakeholders
- Product manager makes final decision

Decision: Build mobile app in Q3 (current plan)

Rationale:
- Strong user demand supports building
- Q3 timing allows finishing AI foundation first
- AI features align better with strategy (do first)
- Mobile app still timely (Q3 not too late)
- Balances strategic alignment and user needs

Not chosen:
- Q2: Too early, AI foundation incomplete
- Q4: Too late, risk losing to competitors
- Don't build: User demand too strong to ignore
```

### 6. Communicate and Act

**Share decision and move forward:**
- Explain rationale
- Address concerns
- Define next steps
- Set success metrics

## Data Quality for Decisions

### 1. Relevance

**Is data relevant to decision?**
- Directly related to options
- Measures what matters
- Timely and current

### 2. Reliability

**Can you trust the data?**
- Accurate collection
- Sufficient sample size
- Statistical significance
- Consistent methodology

### 3. Completeness

**Do you have full picture?**
- Multiple perspectives
- Both quantitative and qualitative
- Historical context
- Future projections

### 4. Actionability

**Can you act on the data?**
- Clear implications
- Within your control
- Specific enough to guide action

## Common Decision Mistakes

### 1. Analysis Paralysis

**Mistake:** Waiting for perfect data
**Fix:** Good enough data, timely decisions

### 2. Confirmation Bias

**Mistake:** Seeking data that confirms preconception
**Fix:** Actively look for contradictory evidence

### 3. HiPPO Dominance

**Mistake:** Highest paid person's opinion overrides data
**Fix:** Present data clearly, make case with evidence

### 4. Ignoring Qualitative

**Mistake:** Only using quantitative data
**Fix:** Combine both types of data

### 5. Not Deciding

**Mistake:** Avoiding difficult decisions
**Fix:** Make decisions, learn from outcomes

## Building Data-Informed Culture

### 1. Democratize Data

**Make data accessible:**
- Self-service dashboards
- Data literacy training
- Clear documentation
- Open access

### 2. Celebrate Learning

**Reward good process:**
- Not just successful outcomes
- Good decisions with bad outcomes
- Learning from failures
- Experimentation

### 3. Share Decisions

**Transparent decision-making:**
- Document decisions
- Explain rationale
- Share outcomes
- Learn together

### 4. Balance Data and Judgment

**Healthy tension:**
- Data informs, doesn't dictate
- Judgment fills gaps
- Experience provides context
- Intuition sparks innovation

## Senior-Level Data-Informed Decisions

1. **Strategic decisions**
   - Not just tactical optimizations
   - Major strategic choices
   - Long-term direction

2. **Decision quality**
   - Improve decision processes
   - Learn from outcomes
   - Build decision frameworks

3. **Organizational influence**
   - Build data-informed culture
   - Train teams in data use
   - Establish best practices

4. **Complex trade-offs**
   - Navigate ambiguity
   - Balance competing priorities
   - Make judgment calls

## Metrics

- Decision velocity (time to decision)
- Decision quality (outcomes achieved)
- Data usage (% decisions using data)
- Learning rate (insights from decisions)
- Stakeholder satisfaction with decisions
