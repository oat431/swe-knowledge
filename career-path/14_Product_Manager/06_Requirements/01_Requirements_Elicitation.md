# Requirements Elicitation

> Elicitation is discovery, not just gathering. Stakeholders don't always know what they need, can't always articulate it, or don't realize what's possible. Elicitation uncovers the real needs beneath surface requests.

## Why Elicitation Matters

**Without proper elicitation:**
- Build what stakeholders say, not what they need
- Miss important requirements
- Discover needs too late
- Build wrong solutions

**With proper elicitation:**
- Understand real needs
- Discover hidden requirements
- Build right solutions
- Reduce rework

## Elicitation Techniques

### 1. Interviews

**One-on-one conversations:**

**Types:**
- Structured (prepared questions)
- Semi-structured (guide, flexible)
- Unstructured (exploratory)

**Best for:**
- Deep understanding
- Sensitive topics
- Complex issues
- Individual perspectives

**Process:**
```
1. Prepare questions
2. Build rapport
3. Ask open-ended questions
4. Listen actively
5. Probe deeper
6. Summarize and confirm
```

**Example questions:**
```
Open-ended:
- "Tell me about your typical day"
- "What challenges do you face?"
- "What would make this easier?"

Probing:
- "Can you tell me more about that?"
- "Why is that important?"
- "What happens when...?"

Closing:
- "What else should I know?"
- "Is there anything we missed?"
```

### 2. Workshops

**Group sessions:**

**Best for:**
- Multiple stakeholders
- Resolving conflicts
- Building consensus
- Complex problems

**Process:**
```
1. Define objectives
2. Invite right stakeholders
3. Prepare agenda and materials
4. Facilitate discussion
5. Capture requirements
6. Follow up with summary
```

**Workshop activities:**
- Brainstorming
- Prioritization exercises
- Process mapping
- Role-playing
- Prototyping

### 3. Observation

**Watch users work:**

**Types:**
- Passive (watch only)
- Active (ask questions)
- Participatory (work alongside)

**Best for:**
- Understanding actual behavior
- Discovering unarticulated needs
- Identifying pain points
- Validating stated needs

**Process:**
```
1. Get permission and explain purpose
2. Observe without interrupting (initially)
3. Take notes on actions, not interpretations
4. Ask clarifying questions
5. Summarize observations
```

**What to observe:**
- Workflows and processes
- Tools and workarounds
- Pain points and frustrations
- Time spent on tasks
- Errors and recovery

### 4. Surveys

**Structured questions to many people:**

**Best for:**
- Large user bases
- Quantitative data
- Validating hypotheses
- Prioritization

**Process:**
```
1. Define objectives
2. Design questions (clear, unbiased)
3. Pilot test
4. Distribute
5. Analyze responses
6. Follow up for depth
```

**Question types:**
- Multiple choice
- Rating scales (1-5)
- Ranking (prioritize options)
- Open-ended (limited)

### 5. Document Analysis

**Review existing materials:**

**Best for:**
- Understanding current state
- Historical context
- Regulatory requirements
- Existing processes

**Documents to review:**
- Process documentation
- System documentation
- User manuals
- Support tickets
- Training materials
- Regulatory requirements

### 6. Prototyping

**Show, don't tell:**

**Types:**
- Paper prototypes
- Wireframes
- Interactive mockups
- Functional prototypes

**Best for:**
- Validating understanding
- Exploring solutions
- Getting concrete feedback
- Complex interactions

**Process:**
```
1. Create low-fidelity prototype
2. Show to stakeholders
3. Gather feedback
4. Iterate
5. Increase fidelity as understanding improves
```

## Elicitation Planning

### 1. Identify Stakeholders

**Who has information?**
- End users
- Business stakeholders
- Technical stakeholders
- Subject matter experts
- Customers
- Support staff

### 2. Select Techniques

**Match technique to situation:**

| Situation | Best Techniques |
|-----------|----------------|
| Complex problem | Interviews, workshops, observation |
| Many stakeholders | Surveys, workshops |
| Conflicting needs | Workshops, interviews |
| Unclear requirements | Observation, prototyping |
| Large user base | Surveys, interviews (sample) |

### 3. Prepare

**Before elicitation:**
- Research context
- Prepare questions/activities
- Schedule sessions
- Prepare materials
- Set expectations

### 4. Execute

**During elicitation:**
- Build rapport
- Listen actively
- Ask open questions
- Probe deeper
- Take good notes
- Confirm understanding

### 5. Document

**After elicitation:**
- Organize notes
- Extract requirements
- Identify themes
- Resolve conflicts
- Share with stakeholders

## Elicitation Best Practices

### 1. Ask "Why" Multiple Times

**Get to root cause:**
```
User: "I need a search feature"
Why? "To find customer information"
Why? "To answer customer questions"
Why? "To provide good service"

Root need: Quick access to customer information
Search is one solution, but not the only one
```

### 2. Focus on Problems, Not Solutions

**Understand the need:**
```
Don't ask: "What features do you want?"
Ask: "What problems are you trying to solve?"
     "What makes your job difficult?"
     "What would make this easier?"
```

### 3. Listen for What's Not Said

**Read between lines:**
- Hesitations
- Workarounds
- Frustrations
- "We've always done it this way"

### 4. Validate Understanding

**Confirm you got it right:**
```
"Let me make sure I understand..."
"So what you're saying is..."
"Is this correct?"
```

### 5. Triangulate

**Multiple sources:**
- Don't rely on single source
- Cross-validate information
- Look for patterns
- Resolve conflicts

## Common Elicitation Mistakes

### 1. Leading Questions

**Mistake:** "Don't you think this feature would help?"
**Fix:** "How would this feature affect your work?"

### 2. Accepting First Answer

**Mistake:** Taking initial response at face value
**Fix:** Probe deeper with follow-up questions

### 3. Ignoring Non-Verbal Cues

**Mistake:** Only listening to words
**Fix:** Watch body language, tone, enthusiasm

### 4. Eliciting from Wrong People

**Mistake:** Only talking to managers, not users
**Fix:** Include all relevant stakeholders

### 5. Not Following Up

**Mistake:** Elicit once, never validate
**Fix:** Share findings, confirm understanding

## Senior-Level Elicitation

1. **Strategic elicitation**
   - Not just feature needs
   - Business outcome needs
   - Strategic requirements

2. **Complex stakeholder groups**
   - Navigate politics
   - Manage conflicts
   - Build consensus

3. **Elicitation leadership**
   - Train teams in elicitation
   - Establish best practices
   - Build elicitation culture

4. **Advanced techniques**
   - Ethnographic methods
   - Contextual inquiry
   - Design thinking

## Metrics

- Requirements coverage (% of needs discovered)
- Requirements accuracy (validated vs. actual needs)
- Elicitation efficiency (time to discover requirements)
- Stakeholder satisfaction with elicitation
- Requirements stability (changes after elicitation)
