# Roadmap Anti-Patterns

> Roadmaps fail in predictable ways. Understanding common anti-patterns helps you avoid them and build roadmaps that actually work.

## Why Anti-Patterns Matter

**Ignoring anti-patterns:**
- Repeat common mistakes
- Waste time on ineffective roadmaps
- Frustrate stakeholders
- Fail to deliver value

**Understanding anti-patterns:**
- Avoid common pitfalls
- Build effective roadmaps
- Set appropriate expectations
- Deliver on commitments

## Anti-Pattern 1: The Feature Factory

**Problem:**
- Roadmap is just a list of features
- No connection to outcomes or strategy
- Measures success by features shipped, not value delivered

**Symptoms:**
```
Q1 Roadmap:
- Customer profile page
- Order history
- Search functionality
- Export feature
- Email notifications
- Dark mode

No mention of:
- Why we're building these
- What outcomes we expect
- How they connect to strategy
```

**Why it fails:**
- Teams build features, not value
- No way to measure success
- Features may not solve problems
- Disconnects from business goals

**Solution:**
- Connect features to outcomes
- Define success metrics
- Link to strategic goals
- Measure outcomes, not outputs

**Example:**
```
Q1 Roadmap:
Initiative: Unified Customer View
Goal: Reduce call handling time by 30%
Features:
- Customer profile page
- Order history
- Search functionality
Success metric: Average call time < 5 minutes
```

## Anti-Pattern 2: The Wish List

**Problem:**
- Everything stakeholders want
- No prioritization or trade-offs
- Unrealistic scope and timelines

**Symptoms:**
```
Q1 Roadmap (everything!):
- Unified customer view
- Mobile app
- AI recommendations
- Advanced analytics
- European expansion
- API marketplace
- Partner portal
- White-label solution

Timeline: Q1 (3 months)
Resources: 1 team
```

**Why it fails:**
- Impossible to deliver
- Sets up for failure
- No focus or priorities
- Stakeholder disappointment

**Solution:**
- Ruthless prioritization
- Explicit trade-offs
- Realistic scoping
- Say no clearly

**Example:**
```
Q1 Roadmap (focused):
- Unified customer view (strategic priority)

Q2 Roadmap:
- Real-time search (builds on Q1)

Deferred:
- Mobile app (Q4, pending research)
- AI recommendations (2027, needs data foundation)
```

## Anti-Pattern 3: The False Precision

**Problem:**
- Specific dates for uncertain work
- Pretending to know the unknown
- Overcommitment to timelines

**Symptoms:**
```
2026 Roadmap:
- Unified view: March 15
- Search: May 22
- Mobile app: August 3
- AI features: October 17

All dates treated as commitments
Despite high uncertainty
```

**Why it fails:**
- Unrealistic expectations
- Disappointment when dates slip
- Pressure to cut corners
- Loss of trust

**Solution:**
- Use time horizons
- Communicate confidence levels
- Use ranges, not dates
- Be honest about uncertainty

**Example:**
```
2026 Roadmap:
Now (Q1): Unified view (March-April) - High confidence
Next (Q2): Search (Q2) - Medium confidence
Later (H2): Mobile app (H2) - Low confidence
          AI features (2027) - Exploring
```

## Anti-Pattern 4: The Set-and-Forget

**Problem:**
- Create roadmap once
- Never update or maintain
- Becomes outdated quickly

**Symptoms:**
- Roadmap from 6 months ago still "current"
- No progress tracking
- No adaptation to learning
- Stakeholders ignore roadmap

**Why it fails:**
- Doesn't reflect reality
- Poor decisions based on stale data
- Loss of trust
- Roadmap becomes irrelevant

**Solution:**
- Regular maintenance
- Progress tracking
- Adaptation to learning
- Regular communication

**Example:**
```
Maintenance cadence:
- Weekly: Progress tracking
- Monthly: Roadmap updates
- Quarterly: Strategic review

Recent updates:
- March 15: Unified view delayed to April (API complexity)
- April 1: Search features added based on research
- April 15: Mobile deferred to Q4
```

## Anti-Pattern 5: The Siloed Roadmap

**Problem:**
- Each team has own roadmap
- No coordination or alignment
- Conflicting priorities and dependencies

**Symptoms:**
```
Engineering roadmap: Technical debt Q1
Product roadmap: New features Q1
Marketing roadmap: Launch Q1

No coordination
Conflicting priorities
Missed dependencies
```

**Why it fails:**
- Misaligned organization
- Resource conflicts
- Missed dependencies
- Incoherent product

**Solution:**
- Aligned roadmaps
- Cross-team coordination
- Shared priorities
- Dependency management

**Example:**
```
Aligned Q1:
Week 1-4: Technical foundation (Engineering)
          Requirements and design (Product)
          Messaging development (Marketing)

Week 5-8: Feature development (Engineering)
          Beta program (Product)
          Sales enablement (Marketing)

Week 9-12: Launch preparation (All teams)
```

## Anti-Pattern 6: The Black Box

**Problem:**
- Roadmap created in secret
- No transparency into process
- Decisions unexplained

**Symptoms:**
- Roadmap appears without context
- No explanation of choices
- Stakeholders surprised
- No input gathered

**Why it fails:**
- Lack of buy-in
- Misunderstanding
- Resistance to roadmap
- Poor decisions (missing input)

**Solution:**
- Transparent process
- Stakeholder involvement
- Clear rationale
- Open communication

**Example:**
```
Transparent process:
1. Gathered input from all stakeholders
2. Used RICE framework for prioritization
3. Made trade-offs explicit
4. Documented rationale
5. Communicated before finalizing

Rationale for Q1 priorities:
- Unified view: Highest RICE score (200)
- Search: Second highest (150)
- Mobile: Lower score (17), deferred to Q4
```

## Anti-Pattern 7: The Moving Target

**Problem:**
- Constant changes
- No stability
- Teams can't plan or execute

**Symptoms:**
- Roadmap changes weekly
- Priorities shift constantly
- Teams frustrated
- Nothing gets finished

**Why it fails:**
- Context switching costs
- Wasted work
- Team frustration
- No progress

**Solution:**
- Stable core priorities
- Scheduled changes
- Change management process
- Balance stability and agility

**Example:**
```
Stable roadmap:
Core (stable for quarter): Unified view
Flexible (can adjust): Feature details
Change process: Monthly reviews, not ad-hoc

Changes this quarter:
- March: Added filter feature (customer feedback)
- April: None
- May: Deferred export (resource constraint)
```

## Anti-Pattern 8: The Output Tracker

**Problem:**
- Measure success by delivery
- Not by outcomes or value
- Ship features, not solutions

**Symptoms:**
```
Q1 Success:
✓ Shipped 12 features
✓ Completed 8 epics
✓ Released 3 versions

But:
- Call handling time unchanged
- Customer satisfaction unchanged
- No business impact
```

**Why it fails:**
- Features without value
- Activity without outcomes
- Busy work
- No business impact

**Solution:**
- Outcome-focused roadmap
- Success metrics defined
- Measure value delivered
- Celebrate outcomes, not outputs

**Example:**
```
Q1 Success:
Outcome: Call handling time reduced 30%
Metric: Average call time 7 min → 5 min
Features delivered: Unified view, search
Business impact: $500K cost savings
Customer impact: CSAT 3.2 → 4.1
```

## Avoiding Anti-Patterns

### Self-Assessment

**Regularly check:**
- Are we building features or outcomes?
- Are we honest about uncertainty?
- Are we maintaining the roadmap?
- Are we coordinating across teams?
- Are we transparent in process?
- Are we measuring outcomes?

### Prevention Strategies

1. **Start with outcomes:**
   - Define success metrics
   - Connect to strategy
   - Measure value, not features

2. **Embrace uncertainty:**
   - Use time horizons
   - Communicate confidence
   - Use ranges, not dates

3. **Maintain rigorously:**
   - Regular reviews
   - Progress tracking
   - Adaptation to learning

4. **Coordinate broadly:**
   - Align team roadmaps
   - Manage dependencies
   - Shared priorities

5. **Be transparent:**
   - Open process
   - Clear rationale
   - Stakeholder involvement

6. **Stabilize core:**
   - Stable strategic direction
   - Flexible tactical execution
   - Managed change process

## Senior-Level Anti-Pattern Avoidance

1. **Recognize patterns:**
   - Spot anti-patterns early
   - Understand root causes
   - Apply appropriate solutions

2. **Build good practices:**
   - Establish roadmap standards
   - Train teams in best practices
   - Create governance

3. **Organizational influence:**
   - Address systemic anti-patterns
   - Influence culture
   - Build roadmap maturity

4. **Continuous improvement:**
   - Learn from mistakes
   - Improve processes
   - Share learnings

## Metrics

- Anti-pattern occurrence rate
- Roadmap effectiveness (outcomes achieved)
- Stakeholder satisfaction
- Team frustration level
- Roadmap stability
