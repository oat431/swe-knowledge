# Roadmap Maintenance

> A roadmap is a living document that must evolve as you learn, as markets change, and as execution reveals reality. Maintenance ensures the roadmap remains accurate, relevant, and useful.

## Why Roadmap Maintenance Matters

**Without maintenance:**
- Outdated information
- Misaligned expectations
- Poor decisions based on stale data
- Loss of trust in roadmap

**With maintenance:**
- Current and accurate
- Reflects reality
- Enables good decisions
- Maintains trust

## Maintenance Process

### 1. Regular Reviews

**Scheduled review cadence:**

**Weekly:**
- Progress tracking
- Blocker identification
- Timeline adjustments
- Team-level updates

**Monthly:**
- Roadmap adjustments
- Priority reassessment
- Stakeholder updates
- Dependency review

**Quarterly:**
- Strategic alignment check
- Major roadmap updates
- Horizon roll-forward
- Lessons learned

### 2. Triggered Updates

**Update when:**
- Strategic direction changes
- Market conditions shift
- Major learnings emerge
- Significant delays occur
- New opportunities arise
- Resources change

**Example triggers:**
```
Trigger: Competitor launches similar product
Update: Reassess positioning, adjust timeline

Trigger: Customer research reveals different need
Update: Reframe problem, adjust features

Trigger: Technical approach fails
Update: Reassess approach, adjust timeline
```

### 3. Update Process

**When updating roadmap:**

1. **Assess impact:**
   - What changes?
   - What's affected?
   - What are trade-offs?

2. **Make decision:**
   - Use prioritization frameworks
   - Consider dependencies
   - Evaluate alternatives

3. **Document changes:**
   - What changed
   - Why it changed
   - When it changed
   - Impact of change

4. **Communicate changes:**
   - Notify stakeholders
   - Explain rationale
   - Update expectations
   - Answer questions

## Maintenance Activities

### 1. Progress Tracking

**Track:**
- Initiative progress
- Milestone achievement
- Timeline adherence
- Goal progress

**Example:**
```
Initiative: Unified Customer View
Progress: 60% complete
Status: On track
Milestones:
✓ Customer data model (complete)
✓ CRM API integration (complete)
→ Order API integration (in progress, 70%)
□ Unified view UI (not started)
□ Knowledge base integration (not started)

Timeline: March 31 (on track)
```

### 2. Priority Reassessment

**Regularly reassess:**
- Are priorities still right?
- Has value changed?
- Has effort changed?
- Are assumptions valid?

**Example:**
```
Original priority: Mobile app (Q3)
Reassessment: Customer research shows web is primary
New priority: Defer mobile to Q4, accelerate search
Rationale: Higher immediate value from search
```

### 3. Dependency Management

**Monitor and update:**
- Dependency status
- Emerging dependencies
- Resolved dependencies
- Blocked items

**Example:**
```
Dependency: CRM API integration
Status: Complete (was: In progress)
Impact: Unblocks unified view development
Next: Proceed with UI development
```

### 4. Timeline Adjustments

**Adjust based on:**
- Actual velocity
- Scope changes
- Blockers
- Resource changes

**Example:**
```
Original: Unified view by March 31
Actual progress: Slower than expected
Adjustment: New target April 15
Rationale: API integration more complex than estimated
Communication: Stakeholders notified, expectations reset
```

### 5. Scope Refinement

**Refine as you learn:**
- Add details as work approaches
- Remove items no longer relevant
- Adjust scope based on learning
- Split large items into smaller

**Example:**
```
Original: "Advanced search features"
Refined: 
- Faceted search (Q2)
- Saved searches (Q2)
- Search analytics (Q3)
- AI search suggestions (Q4)
```

## Maintenance Governance

### 1. Ownership

**Clear ownership:**
- Product manager owns roadmap
- Teams own execution plans
- Stakeholders own input
- Leadership owns strategic direction

### 2. Update Authority

**Who can update:**
- Product manager: All updates
- Teams: Execution details
- Stakeholders: Input and feedback
- Leadership: Strategic changes

### 3. Version Control

**Track changes:**
- Version numbers
- Change logs
- Update dates
- Change rationale

**Example:**
```
Roadmap v2.3 (March 15, 2026)
Changes:
- Unified view delayed to April 15
- Search features added to Q2
- Mobile app deferred to Q4

Rationale: API integration complexity, customer research

Previous: v2.2 (February 28, 2026)
```

### 4. Communication Protocol

**When updating:**
- Immediate notification for major changes
- Regular updates for minor changes
- Documentation of all changes
- Stakeholder-specific communication

## Common Maintenance Mistakes

### 1. Set and Forget

**Mistake:** Create roadmap, never update
**Fix:** Regular reviews and updates

### 2. Update Without Communication

**Mistake:** Change roadmap silently
**Fix:** Communicate all changes

### 3. Over-Update

**Mistake:** Constant changes
**Fix:** Scheduled reviews, trigger-based updates

### 4. Ignore Learnings

**Mistake:** Stick to plan despite evidence
**Fix:** Incorporate learnings into roadmap

### 5. No Version Control

**Mistake:** Don't track what changed
**Fix:** Version control and change logs

## Senior-Level Roadmap Maintenance

1. **Strategic maintenance**
   - Not just tactical updates
   - Strategic alignment checks
   - Long-term coherence

2. **Governance establishment**
   - Define maintenance processes
   - Establish ownership
   - Create standards

3. **Organizational coordination**
   - Coordinate across teams
   - Align roadmaps
   - Manage dependencies

4. **Continuous improvement**
   - Learn from maintenance
   - Improve processes
   - Build better roadmaps

## Metrics

- Roadmap freshness (time since last update)
- Roadmap accuracy (predicted vs. actual)
- Update frequency (changes per quarter)
- Stakeholder satisfaction with updates
- Communication effectiveness
