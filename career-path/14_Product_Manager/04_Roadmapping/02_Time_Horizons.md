# Time Horizons

> Roadmaps must balance commitment with flexibility. Near-term work needs certainty for execution, while long-term work needs flexibility for learning. Time horizons provide this balance.

## Why Time Horizons Matter

**Without time horizons:**
- False precision on uncertain work
- Overcommitment to long-term plans
- Inability to adapt
- Stakeholder disappointment

**With time horizons:**
- Appropriate confidence at each timeframe
- Flexibility where needed
- Commitment where possible
- Honest communication

## Three-Horizon Model

### Now (Current Quarter)

**Characteristics:**
- Committed work
- High confidence (90%+)
- Detailed scope
- In execution

**Content:**
- Specific features and user stories
- Detailed requirements
- Assigned teams
- Defined timelines

**Example:**
```
Now (Q1 2026):
✓ Customer profile page (March 1-15)
✓ Order history integration (March 16-31)
✓ Basic search functionality (April 1-15)
✓ Knowledge base integration (April 16-30)

Confidence: 95%
Status: In progress
```

**Management:**
- Execute according to plan
- Track progress daily
- Address blockers immediately
- Minimal changes allowed

### Next (Next Quarter)

**Characteristics:**
- Planned work
- Medium confidence (70-80%)
- Scoped but flexible
- Ready to start

**Content:**
- Major features and epics
- High-level requirements
- Tentative team assignments
- Estimated timeframes

**Example:**
```
Next (Q2 2026):
→ Real-time search infrastructure (May)
→ Advanced search features (June)
→ Performance optimization (June-July)
→ Mobile responsive design (July)

Confidence: 75%
Status: Planning
```

**Management:**
- Refine scope and requirements
- Prepare teams and resources
- Identify dependencies
- Moderate changes allowed

### Later (Future Quarters)

**Characteristics:**
- Potential work
- Low confidence (40-60%)
- High-level themes
- Subject to change

**Content:**
- Strategic themes
- Major initiatives
- Desired outcomes
- Rough timeframes

**Example:**
```
Later (H2 2026):
? AI-powered recommendations (Q3)
? Predictive analytics (Q3-Q4)
? Mobile native app (Q4)
? European expansion (Q4)

Confidence: 50%
Status: Exploring
```

**Management:**
- Explore and validate
- Conduct research and discovery
- Assess feasibility
- Major changes expected

## Time Horizon Management

### 1. Rolling Planning

**Process:**
- Review quarterly
- Promote "Next" to "Now"
- Promote "Later" to "Next"
- Add new items to "Later"

**Example:**
```
January: Now=Q1, Next=Q2, Later=Q3-Q4
April: Now=Q2, Next=Q3, Later=Q4-2027
July: Now=Q3, Next=Q4, Later=2027
October: Now=Q4, Next=Q1-2027, Later=Q2-Q4-2027
```

### 2. Confidence Calibration

**Adjust confidence based on:**
- Evidence strength
- Technical uncertainty
- Market stability
- Resource availability
- Dependency clarity

**Example:**
```
High confidence (90%+):
- Well-understood problem
- Proven technology
- Stable requirements
- Available resources

Medium confidence (70-80%):
- Some uncertainty
- New but feasible technology
- Requirements may evolve
- Resources mostly available

Low confidence (40-60%):
- High uncertainty
- Unproven approach
- Unclear requirements
- Resource constraints
```

### 3. Commitment Levels

**Match commitment to horizon:**

**Now:**
- Firm commitment
- Detailed planning
- Resource allocation
- Execution focus

**Next:**
- Soft commitment
- Scope definition
- Resource planning
- Preparation focus

**Later:**
- No commitment
- Exploration
- Option preservation
- Learning focus

## Communicating Time Horizons

### 1. Visual Representation

**Use visual cues:**
```
Now (Q1): ████████████████ [Solid, detailed]
Next (Q2): ███████████░░░░░ [Medium, scoped]
Later (H2): ████░░░░░░░░░░░░ [Light, thematic]
```

### 2. Language

**Now:**
- "We will deliver..."
- "Committed to..."
- "Scheduled for..."

**Next:**
- "We plan to..."
- "Targeting..."
- "Aiming for..."

**Later:**
- "We're exploring..."
- "Considering..."
- "Potential for..."

### 3. Expectations

**Set clear expectations:**
```
Now: "These are committed deliverables for this quarter"
Next: "These are planned for next quarter, subject to refinement"
Later: "These are possibilities we're exploring for future quarters"
```

## Common Time Horizon Mistakes

### 1. False Precision

**Mistake:** Specific dates for "Later" items
**Fix:** Use quarters or halves for uncertain work

### 2. Equal Confidence

**Mistake:** Same confidence for all timeframes
**Fix:** Explicitly state confidence levels

### 3. Overcommitment

**Mistake:** Committing to "Later" items
**Fix:** Preserve flexibility for future work

### 4. Ignoring Horizons

**Mistake:** Treating all items as "Now"
**Fix:** Clearly separate and manage each horizon

### 5. Not Updating

**Mistake:** Horizons don't roll forward
**Fix:** Regular quarterly reviews and updates

## Senior-Level Time Horizon Management

1. **Strategic time horizons**
   - Not just quarterly planning
   - Annual and multi-year horizons
   - Strategic initiative sequencing

2. **Uncertainty management**
   - Explicitly communicate uncertainty
   - Plan for multiple scenarios
   - Build optionality

3. **Organizational alignment**
   - Align team planning horizons
   - Coordinate across functions
   - Manage expectations

4. **Adaptive planning**
   - Learn and adjust
   - Incorporate new information
   - Evolve plans intentionally

## Metrics

- Horizon accuracy (predicted vs. actual delivery)
- Commitment reliability (% of "Now" delivered)
- Planning stability (changes per horizon)
- Confidence calibration (predicted vs. actual confidence)
- Stakeholder satisfaction with planning

## Checklist

Before planning:
- [ ] Time horizons defined
- [ ] Confidence levels assigned
- [ ] Commitment levels clear
- [ ] Appropriate detail for each horizon
- [ ] Flexibility preserved where needed

During execution:
- [ ] Horizons reviewed regularly
- [ ] Confidence updated based on learning
- [ ] Items promoted as appropriate
- [ ] Changes communicated
- [ ] Expectations managed
