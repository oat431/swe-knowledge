# React Native Checklist

> Framework-specific checklist for building and shipping mobile apps with React Native.
> Companion to the general [[mobile]] checklist — that one is the contract, this one is the plumbing.
> Covers React Native current: New Architecture (Fabric + TurboModules + JSI) is the default since 0.76, Hermes is the bundled JS engine. Expo (CNG/Prebuild) is the modern starting point.
> Last updated: 2026-11-14 (created: mobile framework layer)

---

## 1. Project Setup & Framework Choice

- [ ] **Expo (managed / CNG) is the default:** `npx create-expo-app`; native projects are generated by Prebuild from your config (Continuous Native Generation). Library installs and upgrades become config changes, not native surgery. Bare React Native only for the exceptions below.
- [ ] **Bare React Native when you genuinely need it:** brownfield embedding into an existing native app, custom native code that config plugins can't express, or toolchain constraints that forbid generated native projects. "We might need native code someday" is not a reason — Expo prebuild covers native code too.
- [ ] **Config plugins for native config in code:** permissions, entitlements, URL schemes, Info.plist/AndroidManifest entries declared as plugins — not hand-edited native files (Prebuild regenerates those). Verify your manifest diff after `npx expo prebuild`:

```bash
npx expo prebuild --clean   # regenerates android/ and ios/ from config
npx expo run:android        # compiles the generated native project end to end
```

- [ ] **app.json / app.config discipline:** one source of truth for name, bundle identifiers, versions, icons, plugins. `app.config.ts` for env-conditional values (dev/staging/prod identifiers and URLs). Never make the generated `android/` + `ios/` dirs your primary editing surface in a CNG project.
- [ ] **TypeScript strict mode:** `"strict": true` plus `noUncheckedIndexedAccess` in tsconfig (RN typings hide implicit anys at the edges) → [[mobile]] §1.
- [ ] **Lockfile committed, environments separated:** CI and dev resolve the same tree (`yarn.lock`/`package-lock.json`/`bun.lock`). Dev/staging/prod via separate bundle IDs and config switching. No hard-coded URLs or keys → [[mobile]] §1.

## 2. Architecture & Runtime

- [ ] **New Architecture is the default:** since React Native 0.76 it is enabled in all new projects (Fabric renderer + TurboModules + JSI). Don't opt out (`newArchEnabled=false`) without a documented third-party blocker; the legacy architecture is maintenance-only. Verify against reactnative.dev before assuming — status is still evolving.
- [ ] **Bridgeless: the async bridge is gone:** JSI lets JS hold direct references to native/C++ objects and call them synchronously — no serialization round-trips over a message bridge. Legacy `NativeModules`-style access runs through interop layers, which are compatibility shims, not the target architecture.
- [ ] **TurboModules for custom native code:** typed specs + codegen → §5. TurboModules register and initialize lazily instead of eagerly at startup, so native module init no longer taxes your launch time — but only if you stop touching unused modules up front.
- [ ] **Hermes is the JS engine:** bundled with React Native, no configuration needed. Release builds compile JS to Hermes bytecode (`.hbc`) at build time for faster startup and lower memory. Confirm release builds actually ship bytecode, and benchmark before/after if startup looks suspicious:

```bash
npx expo run:ios --mode Release   # release-mode run: exercises Hermes bytecode path
```
- [ ] **Codegen is part of the build:** module/component specs are code-generated into native interfaces. Keep specs in source control; run codegen in CI exactly as local builds do, or native and JS silently disagree.
- [ ] **Feature-first JS structure:** shared code separated from platform-divergent code (`*.ios.tsx` / `*.android.tsx` suffixes only where UI genuinely differs). No god components → [[react]] §2.

## 3. Navigation & Screens

- [ ] **Expo Router or React Navigation:** Expo Router (file-based routing over React Navigation) is the Expo default; React Navigation directly for bare or heavily custom setups. Don't roll your own navigator → [[mobile]] §2.
- [ ] **Deep linking per OS:** custom URL scheme + universal links (iOS Associated Domains + `apple-app-site-association`) / App Links (Android `assetlinks.json` + intent filters). Declared via app config/plugins so Prebuild keeps them. Test cold-start deep links with `adb shell am start` / `xcrun simctl openurl` → [[mobile]] §2.
- [ ] **State restoration:** navigation stack survives app kill where UX expects it; at minimum the correct tab survives backgrounding → [[mobile]] §2.
- [ ] **Auth gates at the router level:** one redirect/guard location, not a check in every screen. Unauthenticated deep link → login → back to intended screen → [[mobile]] §7.
- [ ] **Platform back behavior:** Android hardware/gesture back pops the right stack; iOS swipe-back works; modals dismiss predictably and return data to their parent → [[mobile]] §2.
- [ ] **Modals and sheets are routes:** bottom sheets, full-screen modals, and dialogs live in the router, not ad-hoc boolean state — dismiss handling and passing data back to the parent are solved problems → [[mobile]] §2.

## 4. Data & State

- [ ] **TanStack Query-class server state:** every async read through a query, every async write through a mutation. Query key conventions, staleTime tuning, optimistic updates, no `useEffect` + fetch — identical rules to the web side → [[react]] §4.
- [ ] **Client state stays minimal:** Zustand/Jotai-class stores for cross-screen UI state only. Never duplicate server cache in a store → [[react]] §6.
- [ ] **MMKV-class fast KV over AsyncStorage:** synchronous, faster, better for settings and hydration-sensitive state. AsyncStorage is the legacy baseline (async, slower) — acceptable for trivial non-sensitive flags, never for secrets → §12.
- [ ] **Structured data goes in a SQLite-class local DB:** WatermelonDB/Realm-class for relational and synced data. Not KV stores for lists → [[mobile]] §6.
- [ ] **Offline-first:** local store is the source of truth; mutations queue while offline and replay on reconnect; UI shows pending state; conflict strategy documented → [[mobile]] §5–7.
- [ ] **Hydration without a flash:** cached data renders immediately on launch, revalidates in background → [[mobile]] §4.

## 5. Native Modules & Third-Party Code

- [ ] **TurboModules, not legacy native modules:** typed spec + codegen + direct JSI calls. If you wrap a legacy module, remember the interop layer is a bridge back to the old world — budget its removal.
- [ ] **Audit third-party native deps before adding:** maintenance status, New Architecture compatibility, open issues, license. Every native dependency is code you compile into both binaries → [[02 Dependency & Supply Chain]].
- [ ] **Permission surface review:** libraries inject manifest entries (camera, location, tracking). Diff `AndroidManifest.xml` / `Info.plist` after Prebuild; each unexplained permission is a rejection risk and a user-trust cost → [[mobile]] §14.
- [ ] **iOS privacy manifests:** third-party SDKs may ship `PrivacyInfo.xcprivacy`; your app needs its own for required-reason APIs. Missing or wrong manifests stall submission → [[mobile]] §14.
- [ ] **Platform API misuse risks:** location, background modes, advertising/tracking APIs trigger OS permission prompts and store review — request at point of use, with purpose strings that say why → [[mobile]] §14.

## 6. Build & Distribution

- [ ] **iOS builds require macOS:** the Xcode toolchain only runs on macOS — iOS CI runners must be macOS (hosted or self-hosted) → [[mobile]] §13.
- [ ] **EAS Build-class cloud builds vs self-hosted Fastlane:** managed cloud builds for speed and low ops; Fastlane on your own macOS runners when you must control signing, toolchains, or enterprise distribution. One pipeline, not a hybrid mess.
- [ ] **Android Gradle builds:** Gradle + R8 shrinking/obfuscation on release; lock Gradle and native dependency versions for reproducibility → [[mobile]] §13.
- [ ] **Signing never touches git:** iOS certificates + provisioning profiles managed via EAS credentials or Fastlane match; Android keystore in CI secrets — losing the keystore means a new Play listing → [[mobile]] §13.
- [ ] **Store submission is the master checklist's job:** screenshots per display family, privacy labels, data safety, Play Billing Library 8+ and target API level rules → [[mobile]] §13–14. Cross-link; don't re-litigate here.
- [ ] **Reproducible, cached builds:** same commit → same artifact; dependency caches (node_modules, Gradle, CocoaPods, EAS build cache) in CI so builds stay under budget → [[mobile]] §13.

## 7. OTA Updates

- [ ] **Self-hosted code-push-server or Expo Updates/EAS Update-class service:** Microsoft's hosted CodePush and App Center are retired (2025-03-31) — never plan around them. Rollback capability is non-negotiable → [[mobile]] §15.
- [ ] **JS-only changes ship OTA; native changes need a store release:** any change to native dependencies, permissions, entitlements, or native code is a store build. OTA carries the JS bundle and assets, nothing else.
- [ ] **Bundle/runtime compatibility:** the OTA bundle must match the runtime the binary ships (Hermes bytecode targets the bundled engine). Don't push a bundle built against a newer runtime to older binaries.
- [ ] **Staged rollout + fast rollback:** push to a cohort, watch crash-free rate and key metrics per cohort, halt on regression → [[mobile]] §15.
- [ ] **Treat the update channel as production infrastructure:** signed updates, authenticated publishing, channel separation (dev/staging/prod). A compromised update channel is remote code execution on every install → [[security]].

## 8. Debugging & Dev Tools

- [ ] **React Native DevTools is the debugger:** introduced with RN 0.76, it's the standard JS debugging/inspection workflow. Flipper is out of the React Native workflow — don't build tooling or docs around it.
- [ ] **Know Metro's behavior:** dev server vs release bundle; `--reset-cache` when module resolution goes weird after native changes; monorepos need explicit watchFolders/watchman config or you debug phantom "module not found" errors.
- [ ] **Platform debugging when JS lies:** Xcode + Instruments (iOS), Android Studio profiler + `adb` (Android) for native-side and memory issues. JS stack traces don't show what happens across JSI calls.
- [ ] **Network inspection on real traffic:** DevTools network panel or a proxy against a real device — simulator network conditions are fiction.
- [ ] **Reproduce in release mode:** most shipping bugs only appear with Hermes bytecode, R8, and production APIs. Debug-mode green ≠ shipped → [[mobile]] §9.
- [ ] **Release logging hygiene:** `console.log` stripped from production bundles (Babel/Metro transform); crash reporting SDK symbolicates JS stack traces on both OSes → [[mobile]] §15.

## 9. Performance

- [ ] **Hermes startup is the startup lever:** measure cold start to interactive content; release builds must ship `.hbc` bytecode (§2). Defer non-critical init (analytics, crash SDKs) until after first frame → [[mobile]] §9.
- [ ] **List virtualization everywhere:** FlatList/FlashList-class virtualization for any dynamic list; constant item height where possible; never a scroll container with N mounted rows.
- [ ] **JS thread vs UI thread:** heavy JS work (large JSON parsing, crypto, sync storage storms) blocks interaction. Defer non-urgent work (`InteractionManager`-class deferral), keep animations on properties the UI thread can drive without JS round-trips.
- [ ] **Re-render discipline is React discipline:** stable keys, derived state, targeted memoization → [[react]] §7. The RN twist: every re-render marshals into native views, so it costs more than on the web.
- [ ] **Memory on low-end Android:** profile on a cheap 2–3GB device, not the flagship. Leaked listeners and decoded full-size images kill low-RAM phones first → [[mobile]] §9.

## 10. Testing

- [ ] **Jest + React Native Testing Library:** component and hook behavior tests; query by role/label, not a `testID` scavenger hunt. Mock the network at the boundary.
- [ ] **E2E with Maestro/Detox-class tools:** critical flows (onboarding, login, core action, purchase) on emulators and real devices → [[mobile]] §11.
- [ ] **Packaged-build smoke tests per OS:** run smoke flows against the real release artifact (bundled JS + native), on both iOS and Android. Metro-backed dev builds don't exercise bytecode, R8, or prod config.
- [ ] **Upgrade tests:** install the new build over the old one (persisted state, DB migrations, deep links, and OTA'd JS over an older binary). Never lose user data on update.
- [ ] **CI gates on every PR:** lint + typecheck + unit/component tests; E2E nightly and pre-release; low-end Android and oldest supported iOS in the device matrix → [[qa]], [[mobile]] §11.

## 11. Accessibility

- [ ] **RN accessibility props on everything interactive:** `accessibilityRole`, `accessibilityLabel`, `accessibilityLiveRegion`-class props; decorative elements hidden from screen readers; labels say what the control does ("Add item to cart"), not what it is ("button").
- [ ] **Test with real screen readers:** VoiceOver on a physical iPhone, TalkBack on a physical Android device — complete the core flow eyes-free. Emulator a11y tooling misses real issues → [[mobile]] §12.
- [ ] **Dynamic type / font scaling:** respect system font scale; layouts survive the largest accessibility size without truncating critical text → [[mobile]] §12.
- [ ] **Touch targets and focus:** 44–48dp minimum targets; logical focus order; focus moves into modals on open and returns to the trigger on dismiss → [[mobile]] §12.
- [ ] **Reduce motion honored:** respect the OS reduce-motion setting — simpler transitions, no auto-animating carousels.
- [ ] **State exposed, not just labels:** toggles and controls announce checked/disabled/busy state (`accessibilityState`-class props); live regions announce async results (form errors, saved status), not just static text.

## 12. Security & Privacy

- [ ] **Secure storage for secrets:** Keychain/Keystore-backed libraries only. AsyncStorage and MMKV-class KV are plain storage — tokens in AsyncStorage is the classic RN credential leak → [[02 Secrets Management]].
- [ ] **SSL pinning decision:** pin certificates/public keys in the networking layer if the threat model requires it; plan pin rotation and backup pins; handle pin failure gracefully → [[security]], [[mobile]] §10.
- [ ] **App Tracking Transparency + permission prompts (iOS):** ATT before any cross-app tracking; every permission string explains why, not what — both are store-review items → [[mobile]] §14.
- [ ] **Deep-link input validation:** links and notification payloads carry attacker-controlled parameters — validate and sanitize before navigating or fetching.
- [ ] **The JS bundle is readable, full stop:** Hermes bytecode is not obfuscation; anything in the bundle is extractable from the binary. Public config only in the client; sensitive operations server-side → [[security]].

## Quick Sanity Check Before Release

- [ ] Release build ships the New Architecture (no accidental `newArchEnabled=false` inherited from an old template) and Hermes bytecode — cold start measured on a low-end Android device
- [ ] OTA round-trip works end to end: staged push → cohort metrics → rollback tested; the native-dependency change correctly went to the store, not OTA
- [ ] Deep links open the right screen from cold start on both OSes (universal links / App Links verified on real devices)
- [ ] Tokens live in Keychain/Keystore-backed storage, not AsyncStorage — verified by grepping the storage layer
- [ ] VoiceOver and TalkBack complete the core flow; max font scaling breaks no layout
- [ ] E2E smoke suite passes against the packaged release build (not Metro dev mode) on iOS and Android
- [ ] Final `npx expo prebuild` manifest diff reviewed: no surprise permissions, entitlements, or missing privacy manifests from third-party plugins
- [ ] iOS artifacts built on a macOS runner, signing material never touched git, both binaries install over the previous release without losing data
